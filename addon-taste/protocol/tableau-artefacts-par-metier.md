## Livrable opérateur — Addon de capture de goût

**Ce que c'est.** Chaque métier a un *objet natif* (ce sur quoi sa lame tranche vraiment) et un *canal révélé* (la modalité qui force le geste, pas le discours). L'addon sert des artefacts de classification (garde / jette / recombine), puis une phase d'injection (la personne apporte ses propres pièces). L'or est dans l'écart **déclaré ↔ révélé**.

**État réel du code** (`addon-taste/interviewer/`) : `lib/pools.ts` ne contient que `sally` + `john` (pools image) ; `app/api/classify/route.ts` = moteur image adaptatif, renvoie `noPool` pour tout le reste ; assets sur Supabase bucket public `decks/` (jamais hotlink Mobbin, jamais commité). Twins déjà capturés : Sally, Tessa, John. **Le moteur text-deck (scénario/concept verdict-masqué) n'existe pas encore** — c'est le trou structurel.

**Deux surfaces techniques à ne jamais confondre** : (1) `/api/classify` = écrans (image) ; (2) text-deck verdict-masqué = scénarios + concept-texte. Un même métier (John, Sally) roule sur les DEUX.

### Plan de build priorisé (ratio impact / faisabilité)

Le principe : **une seule brique — le moteur text-deck verdict-masqué — débloque le cœur-de-métier de 8 rôles à coût de sourcing nul.** On la câble d'abord, puis on empile les canaux du moins cher (liens/vidéos publics) au plus cher (screen-records à produire).

1. **Moteur text-deck verdict-masqué** (surface distincte de `/api/classify`). *Impact max / faisabilité max* : zéro sourcing (texte auto-écrit, toujours accessible, jamais de lien mort). Débloque le CŒUR de John (KILL/SHIP + ROADMAP, 4), Tessa (5 forks), Camille (concept-texte natif, 2+), Winston (4), Backend (1+), Nadia (7), Dara (3 scénarios + North Star), Sally (3 nudges). Aujourd'hui `route.ts` renvoie `noPool` sans que le deck existe. **C'est le keystone.**

2. **Contrôle de non-bruit §2.3b câblé DANS le moteur** (re-service de doublons, ordre brouillé, ~20 min). *Impact fort / faisabilité forte* : mécanisme unique transverse. **Obligatoire** pour les profils où le canal révélé n'est PAS prouvé (Tessa, Winston, Backend, Dara, Camille) AVANT tout croisement déclaré↔révélé. Pour Dara, encoder les DEUX doublons distincts (STRICT = fiabilité ; arrange/dérange = raisonnement motivé).

3. **Renderer lien-doc + vidéo-embed, avec snapshot Wayback discipliné.** *Impact fort / faisabilité forte* : sourcing = URLs publiques curées, pas de production. Débloque Tessa (Radix/Carbon/Polaris/Primer + Airbnb conf), Nora (Mailchimp/GOV.UK/Polaris style guides), Winston (Prime Video + Choose Boring + DHH + Netflix conf), Backend (Stripe/GitHub docs, Discord Eng, Metz, McKinley), Camille (foresight, Liquid Death, Nike, Patagonia, purpose figé), Margaux partiel (NASA doc + MTV/Oatly/Airbnb vidéo). Règle : ré-héberger/snapshotter, jamais un lien qui pourrit ; vérifier l'exactitude factuelle (ex. Discord = Mongo→Cassandra→Scylla, jamais Postgres).

4. **Extension du pipeline Mobbin→Supabase (déjà prouvé Sally/John) à Nora.** *Impact bon / faisabilité forte* : réutilise à l'identique. Écrans microcopy → `decks/nora/` ; accroches/pubs (Marketing Examples, Ads of the World, D&AD) → MÊME bucket `decks/nora/` (une seule pipeline durable, pas de Wayback à la traîne).

5. **Pool image Dara — dataviz publique.** *Impact bon / faisabilité moyenne-forte* : sources publiques/gratuites (Our World in Data, r/dataisugly, Tyler Vigen, captures Spotify Wrapped, decks « +300% », infographies xG, sondages à marge cachée) → bucket. Nouvelle curation mais zéro paywall.

6. **Pool image Margaux — brand-natif (PAS Mobbin).** *Impact fort (cœur image-first) / faisabilité moyenne* : curation manuelle Brand New/BP&O, Fonts In Use, The Dieline, Are.na (téléchargé, servi depuis bucket) → `decks/margaux`. Plus manuel car aucun MCP ne sert la matière primaire de marque. Attention : pool PARTAGÉ avec Camille, deux clés de décision distinctes (intention vs craft) pour éviter la pollution de lentille au runtime.

7. **Vidéos À PRODUIRE — le vrai coût.** *Impact haut (cœur-de-métier) / faisabilité basse* : Sally items 13-14 (micro-interaction + nav traversée = le seul cœur-de-métier encore non servi) et Kai screencasts perf + a11y (à enregistrer/synthétiser). Screen-records courts hébergés comme les pools ; repli si non hébergeable → séquence de frames-clés. À faire après que le squelette textuel/image porte déjà la classification.

8. **Ingestion des injections + interchangeabilité.** *Impact fort / faisabilité moyenne* : ré-héberger l'upload de l'injecteur (screen-record/capture) ou suivre un lien public durable (App Store/web) ; jamais dépendre d'une URL Mobbin vivante. Les injections rejoignent le pool → stimuli pour comparer les jumeaux (interchangeabilité).

**Séquence de valeur** : 1+2 (le squelette qui fait tourner 8 métiers gratuitement) → 3 (les liens/vidéos publics qui remplissent Tessa/Winston/Backend/Camille/Nora) → 4+5 (image via pipelines prouvés) → 6 (Margaux brand-natif) → 7 (vidéos coûteuses, dont le trou Sally) → 8 (injection). Les métiers déjà servis en image (Sally stills, John) restent en prod ; on ne casse pas le framing neutre (marque masquée) que le pool bâti fait déjà bien.
